# dsh-ct-norm —— CT 报告实体归一化

把中文 CT 报告里的**自由描述**（「右肺上叶见一 2.3cm 结节影」「纵隔及右肺门见多发肿大淋巴结」
「肝内多发低密度灶」…）按本地人工整理的词表，**确定性**映射到 **MeSH 2026 标准概念**
（规范名 + `mesh:D######` 编号 + 树号）。

要解决的痛点很具体：**同一个影像发现，临床医生的写法五花八门**——
「胸腔积液 / 胸膜腔积液 / 胸水 / 胸腔内积液」是同一个概念；
「淋巴结肿大」和「肿大淋巴结」也是。下游要做统计、检索、结构化入库，就得先把它们收敛到同一个编号上。

**全程离线，不调用模型。** 归一化只走两条路径：**词表命中**，或**「部位 + 形态学词」的固定规则组合**。
因此结果可复现、可审计——同一段报告跑一百次，结果逐字节相同。

---

## 1. 一分钟看懂它凭什么可信

这个插件最怕的不是「漏」，而是**看起来规范、其实是错的编码**。
所以整个设计围绕一条性质：**归一化结果里的每一个 MeSH 编号都必然来自 NLM 索引**。

| 做法 | 后果 |
| --- | --- |
| 源词表里**只写 MeSH 英文规范名**，不写编号 | 人没有机会写错编号 |
| 构建时把规范名拿去 NLM 索引**反解**，反解不到就**构建失败** | 编号只有一个来源 |
| 运行时只读**从索引提取的 370 条概念子集** | 插件在物理上产不出子集之外的编号 |
| 打包脚本扫描源文件，出现手写 `D######` 就**拒绝打包** | 这条性质不会在某次手改后悄悄失效 |
| 测试遍历**每一个别名**，验证它真的能命中 | 「写进词表」≠「真的能用」 |

以及一条同样重要的：**MeSH 收录不了的东西，它就不映射，并如实报出来。**
MeSH 主题词表以**疾病实体**为粒度。磨玻璃影、毛刺、分叶、低密度灶、壁增厚、气液平
这类**影像描述性征象在 MeSH 里根本没有对应概念**。硬映射只会造出错误编码，
所以它们统一进「未归一化」栏并附上原因。

| 事实 | 值 |
| --- | --- |
| 写法条目 | 327（解剖 122 / 征象病变 134 / 肿瘤概念 36 / 疗效评估与检查 27 / 泛化形态学 8） |
| 词表别名 | 2057（中文 1539 / 英文 518） |
| 匹配表里的表面写法 | **2190**（词表别名 2057 ＋ 未归一化征象词表 133） |
| 可产出的 MeSH 概念 | **370**（子集上限，硬边界） |
| 「未归一化」征象词 | 33 组 |
| 随包数据体积 | 约 250 KiB（**不含** 74 MiB 全量 MeSH 索引） |
| 依赖 | **零 npm 依赖**；运行时**不联网、不调用模型** |
| 测试 | `node test-ct-norm.mjs` —— 179 项检查 |

## 2. 安装

前提：Node.js ≥ 22，DSH 已安装，且有一个 Web profile（下例为 `web`）。

```powershell
# 打包（产出 dsh-ct-norm-0.1.1.tgz）
pwsh -File build-package-ct-norm.ps1

# 安装（升级时务必先删后装）
dsh plugin --profile web remove dsh-ct-norm
dsh plugin --profile web add file:<tgz 的绝对路径>
```

装完重载或重启 DSH：侧边栏会出现「CT 归一化」入口。

> 与同仓的 `dsh-onco-lexicon` / `dsh-lit-translate` 一样，**用 tgz 安装，不要用 `link:`**
> （原因见那两个插件的 README：junction 与裸模块解析的问题）。
> 本插件的 tgz 很小（约 250 KiB），可以随源码一起走 git，不需要额外的数据分发步骤。

## 3. 给智能体的两个工具

### `ct_norm` —— 归一化一段报告原文

参数：`text`（必填）、`format`（`text` 默认 / `json`）。

拿一段真实风格的中文 CT 报告跑，输出（节选）：

```
CT 报告实体归一化（本地词表 + MeSH；不联网、不调用模型、不做推断）
词表：dsh-ct-norm 0.1.1，327 条写法条目 / 2190 个表面写法 / 370 个 MeSH 概念；词表基于 MeSH 2026

原文 264 字，切分 13 句 / 26 小句；命中 17 个实体（9 个不同 MeSH 概念），未归一化 5 处，仅识别到部位 1 处。
属性统计：否定 2 处、可疑/不确定 5 处、歧义待定 2 处。

一、归一化结果（17 条）
1. 「结节影」→ Solitary Pulmonary Nodule（mesh:D003074，C08.381.884） ＋ Multiple Pulmonary Nodules（mesh:D055613，…）
   部位：Lung（mesh:D008168）｜绑定：同句（较弱）｜段落：检查所见｜词条：morph-nodule｜侧别:右｜尺寸:2.3cm(23mm)
   ▸ 歧义；规则组合
   ⚠ 数量词缺失，Solitary / Multiple Pulmonary Nodules 二者无法判定，已同时列出。
2. 「肺癌」→ Lung Neoplasms（mesh:D008175，C04.588.894.797.520）
   部位：Lung（mesh:D008168）｜绑定：同句（较弱）｜段落：检查所见｜词条：lung-neoplasms｜尺寸:2.3cm(23mm)
   ▸ 可疑（考虑）
3. 「小结节」→ Multiple Pulmonary Nodules（mesh:D055613，…）
   部位：Lung（mesh:D008168）｜绑定：同小句｜词条：morph-nodule｜数量:多发｜侧别:双｜尺寸:5mm
4. 「转移瘤」→ Neoplasm Metastasis（mesh:D009362，C04.697.650） ＋ Liver Neoplasms（mesh:D008113，C04.588.274.623）
   部位：Liver（mesh:D008099）｜绑定：同句（较弱）｜词条：morph-metastasis
   ▸ 可疑（考虑）；规则组合
   ⚠ 「转移 + 部位」按规则给出该部位的肿瘤概念（如 Liver Neoplasms）与 Neoplasm Metastasis；规则外推，建议人工确认。
5. 「肿大淋巴结」→ Lymphadenopathy（mesh:D000072281，C15.604.338）
   部位：Retroperitoneal Space（mesh:D012187）｜绑定：同小句｜词条：lymphadenopathy
   ▸ 否定（未见）

- 「边缘毛糙」—— MeSH 无对应概念（恶性征象描述）。这类征象临床意义大，但 MeSH 没有对应主题词
- 「胸膜未见明显增厚」（部位：Pleura）—— MeSH 主题词表未收录（MeSH 2026 索引中 pleural thickening 无命中）
- 「低密度灶」—— MeSH 无对应概念（密度描述，需结合部位与增强表现才能定病）

三、概念汇总（按 MeSH 编号去重，9 个）
- Neoplasm Metastasis（mesh:D009362，C04.697.650）出现 2 次（可疑 2）
- Multiple Pulmonary Nodules（mesh:D055613，…）出现 2 次
- …

四、仅识别到部位、未绑定任何病变（1 处）
- 「胸部」→ Thorax（mesh:D013909）

五、边界与免责（请连同上面的结果一起转述）
- 本工具只做**词表命中**与**固定规则组合**，不做模型推断、不联网。上表未出现的写法即词表未收录；
  「未归一化」一栏是刻意保留的——MeSH 主题词表以疾病实体为粒度，磨玻璃影、毛刺、低密度灶这类
  影像描述性征象在 MeSH 里没有对应概念，硬映射只会造出看着规范、实则错误的编码。

- 「部位 + 转移/占位」类结果是规则外推（标了「规则组合」），不等于病理诊断，需人工确认。
```

`format: "json"` 返回结构化结果（`entities` / `unmapped` / `sites` / `stats` / `integrityErrors`），
供下游程序消费。

### `ct_lexicon` —— 查词表本身

回答「为什么这个写法没被识别出来」「词表里有没有 XX」「XX 对应哪个 MeSH 编号」：

```powershell
ct_lexicon({ query: "胸腔积液" })        # → Pleural Effusion（mesh:D010996），列出全部中文/英文写法
ct_lexicon({ query: "mesh:D008113" })    # 按编号查 → Liver Neoplasms，并指出谁在用它（liver 条目的 neoplasm）
ct_lexicon({ kind: "morphology" })       # 按类别浏览（泛化形态学词，靠组合规则出概念）
```

输出的每条例名会标出**哪些写法是「近似映射」**（带 `*`）——即外延与 MeSH 概念不完全一致的写法，
例如「肺门肿块」→ Lung Neoplasms 是近似（肺门团块也可能是肿大淋巴结或血管影），
而「肺癌」→ Lung Neoplasms 是精确对应，不会被误标。

## 4. 给人用的侧边栏面板

「归一化」页：粘贴报告 → 一键归一化 → 四栏结果（归一化 / 未归一化 / 概念汇总 / 仅识别到部位），
可复制精简结果或导出 TXT。

「词表」页：检索条目、按类别浏览、查看「未归一化征象词表」（33 组，含每组**为什么没有归一化**）。

界面刻意把「未归一化」和命中结果**并排**呈现——一个只显示命中的界面，
会让人以为报告里每个描述都已被规范化，那是这个工具最危险的误用方式。

## 5. 归一化到底怎么做的

### 5.1 先屏蔽修饰词，再匹配

中文报告写「右侧胸腔**少量**积液」，而概念写法是「胸腔积液」——中间插了「侧」「少量」，
直接子串匹配是**匹配不上**的。所以先把这些词从「匹配用的骨架文本」里摘掉：

```
原文     右侧胸腔少量积液，胸膜未见明显增厚
骨架      胸腔积液,胸膜增厚          ← 修饰词与极性词被摘掉
```

而侧别、程度这些信息**一个字都不丢**：属性判定一律读**原文**，在属性栏里回显。
所以「未见胸腔积液」的「未见」不会被摘掉，否定照样判得出来。

### 5.2 两条匹配通道（关键设计）

但有些别名**本身就含这些词，而且中文里没有别的写法可选**：

* `无病生存` / `无进展生存` 含「无」
* `多发性骨髓瘤` 含「多发」
* 而 `椎体压缩骨折` 又要能匹配「椎体**多发**压缩骨折」

只匹配骨架 → 前两条永远命中不了；只匹配原文 → 第三条又接不上。
所以别名分两桶：不含屏蔽词的走骨架通道，含屏蔽词的走原文通道，结果按
「起点升序、跨度降序」贪心合并（等价于全局最长优先）。

> 这一条是**测试逼出来的**：加「每个别名都必须能命中」的检查后，
> 立刻抓出 `无病生存` 与 `多发性骨髓瘤` 两批死别名。

### 5.3 极性：否定 vs 不确定

中文报告里最容易写反语义的一处：

| 写法 | 含义 | 工具判定 |
| --- | --- | --- |
| 未见胸腔积液 | 没有积液 | `negated: true` |
| **不除外**转移 | **有可能**是转移 | `uncertain: true`，**不是**否定 |
| 考虑转移瘤**可能** | 倾向转移 | `uncertain: true` |

「不除外」里含「除外」，所以判定顺序必须是**先不确定、后否定**。
这个先后关系在 `lib/text.js` 里写死并附说明，测试里专门有一条覆盖它。

否定/不确定的作用域是**小句**（逗号/分号切分）：
「未见胸腔积液，肝内见转移灶」两个小句极性相反，不会互相污染。
顿号「、」**不**作切分点，否则「未见胸腔积液、腹水」会让「腹水」丢掉否定。

### 5.4 部位与病变的组合

报告里「部位 + 病变」常常隔几个字、甚至跨小句：

```
肝内见多发低密度灶，考虑转移瘤可能。
└─ 部位 Liver ─────┘        └─ 概念 Neoplasm Metastasis
                             ↓ 组合规则
                    Liver Neoplasms ＋ Neoplasm Metastasis
```

绑定策略按优先级：**同小句紧邻** → **同句内最近的部位**（跨小句，输出里标为「同句（较弱）」）
→ **概念之后的部位**（「转移至肝」）。绑定方式原样回显，因为跨小句绑定比同小句弱，需要人多看一眼。

规则组合只做这几种，全部写在 `data/src/50-morphology.json` 与 `lib/normalize.js` 里：

| 形态学词 | 组合结果 |
| --- | --- |
| 转移瘤 / 转移灶 / 转移 | ＋ 该部位肿瘤概念；部位是淋巴结时用更精确的 **Lymphatic Metastasis** |
| 癌 / 肿瘤 / 恶性肿瘤 | 该部位肿瘤概念 ＋ 组织学概念 |
| 占位 / 肿块 / 团块 | 该部位肿瘤概念，并明确标注**规则外推、不等于病理诊断**；无部位则不映射 |
| 结节 | 肺：按单发/多发二选一，数量缺失时**报歧义**；甲状腺：查表得 Thyroid Nodule；其它部位：不映射 |
| 病灶 / 病变 | **一律不映射**（性质未知，任何映射都是猜测） |
| 复发 | Neoplasm Recurrence, Local（＋ 该部位肿瘤概念） |

### 5.5 歧义不替用户选

「肺结节」在 MeSH 里对应**两个不同描述符**：`Solitary Pulmonary Nodule` 与
`Multiple Pulmonary Nodules`。报告没写单发还是多发时，工具**同时给出两个候选**并说明待确认的问题，
而不是默认取一个——因为这两个编号在下游统计里含义不同。

## 6. 数据是怎么合出来的

```
NLM MeSH 2026 (desc2026.xml / supp2026.xml)
        │  mesh_build.py build                     （工作区脚本）
        ▼
mesh_out/mesh_index.bin         74 MiB 全量索引，355,232 条记录 / 840,392 条术语
        │  build-ct-lexicon.mjs                   （本插件自带，只读索引）
        │  ↑ data/src/*.json  人工整理的 327 条词表（**只写 MeSH 英文规范名**）
        ▼
data/mesh.subset.jsonl          370 条概念子集（规范名/释义/树号）
data/ct.lexicon.jsonl           327 条别名条目（含反解出的编号）
data/ct.manifest.json           条数、源文件 sha256、MeSH 版本与索引指纹
```

重建步骤与写作规范见 [`data/README.md`](data/README.md) 与 [`data/src/SCHEMA.md`](data/src/SCHEMA.md)。
源文件与 `data/` 一起随包分发，所以**任何人都能用同一份输入复现同一份产物**。

## 7. 覆盖范围与已知限制（请照实读）

1. **覆盖 = 词表本身。** 词表没收录的写法就是识别不出来，工具会如实报进「未归一化」。
   当前 327 条条目主要覆盖胸、腹盆腔、神经、骨肌的常见 CT 征象与肿瘤概念，**不是**全量放射术语库。
2. **MeSH 的粒度限制，不是本插件的 bug。** 影像描述性征象（磨玻璃影、毛刺、分叶、
   低密度灶、强化、钙化、壁增厚、胸膜增厚…）在 MeSH 主题词表里没有对应概念。
   MeSH 2026 全量索引实测：`pleural effusion`（D010996）、`lymphadenopathy`（D000072281）、
   `spinal cord compression`（D013117）等有命中；而 `ground-glass opacity`、`spiculated margin`、
   `liver metastasis`、`bowel wall thickening`、`osteolytic lesion` **一条都没有**。
   这些一律进「未归一化」，不猜。
3. **属性取自动词所在的小句，不保证逐词修饰。** 「纵隔及右肺门见肿大淋巴结」里的「右」
   修饰的是肺门而不是淋巴结，但工具会把「侧别：右」挂在淋巴结实体上。输出里已用注释说明，
   请以原文复核。
4. **近似映射带标记。** 「肺门肿块」→ Lung Neoplasms 这类外延不完全一致的写法，
   在 `ct_lexicon` 里带 `*`，在 `ct_norm` 输出里标「近似映射」。精确对应（如「脓肿」→ Abscess）
   不会被误标。
5. **不产出中文译名。** MeSH 只有英文。条目里的中文是本插件自建的**临床用语对照**，
   不是 MeSH 官方中文名，不得引用为「MeSH 中文名」。
6. **不做否定之外的语义推断。** 工具不判断「这个结节像不像恶性」，只做术语归一化。
7. **不是诊断工具。** 结果不构成诊断意见。

## 8. 测试

```powershell
# 前置：插件目录下要能解析 @deepseek-ai/dsh-tools（DSH 自带，不随插件发布）
$tools = Join-Path $env:LOCALAPPDATA 'Programs\ds-harness-desktop\runtime\host\node_modules\@deepseek-ai'

```

179 项检查，分 14 节。其中值得单独说的几条：

* **[2] 诚实性不变量**：源文件里不得出现手写 MeSH 编号；词表引用的每个概念都要在子集里、
  名字要对得上；跑一段大报告，产出的每个编号都要在子集内。
* **[4] 极性**：「不除外转移」必须判成**不确定**而不是否定（语义反转是这类工具最危险的错）。
* **[9] 近似标记精确到位**：「脓肿」不标近似、「化脓性病变」标近似。
* **[14] 逐别名可命中**：遍历 2190 个别名逐个验证。这一条抓出过两批死别名。

## 10. 版本

### 0.1.0

首版。`ct_norm` / `ct_lexicon` 两个工具 + 侧边栏面板 + 327 条词表 / 370 条 MeSH 概念子集。

设计过程中被测试与探测推翻并修正的几处，如实记录：

* **最长优先的实现写错**，第一个候选就越界导致几乎全部落空（冒烟测试抓到）；
* **「无病生存」「多发性骨髓瘤」永远命中不了**——极性词/修饰词被屏蔽后别名被拆坏，
  改为双通道匹配（逐别名测试抓到）；
* **`甲状腺结节` 从未被收录**，而形态学条目的 note 却声称「有独立条目」（测试抓到假声明）；
* **`searchLexicon` 只查了 `mesh` 字段**，漏了 `neoplasm` / `candidates`，
  按 `mesh:D008113` 一条都查不到；
* **`胸膜增厚` 被错绑到隔壁小句的肺**（尺寸与部位绑定都改成了限定在同小句/同句内）；
* **`approx: true` 把整条别名都标成近似**，连「脓肿→Abscess」这种精确对应也带警示，
  已收敛为「只标真正近似的别名」（34 条）；
* **尺寸归属错误**：上一句的「最大短径约1.5cm」被算到下一句的「胸腔积液」头上，
  改为「先同小句、再同句」的搜索范围。

### 0.1.1 —— 六类抽取缺陷（单位误命中、极性与数量的位置判定、部位不丢）

这一版**没有新增概念**，只修抽取层的错。每一条都是实测出来的，测试里都留了回归（`test-ct-norm.mjs` 第 15 节）：

* **单位 `mm` 被当成 Multiple Myeloma**。拉丁别名在数字后面不许起止：`5mm`、`５ｍｍ`、
  `3 MM`、`mmol/L` 一律不再命中，而「患者 MM 诊断明确」照常命中。中文报告里毫米是出现频率
  最高的单位，旧行为等于把每一处径线都变成一条「多发性骨髓瘤」。
* **否定整小句生效 → 极性反转**。「肝内见转移灶、未见腹水」里的「转移灶」曾被标成否定
  （「、」不切小句，是为了让「未见胸腔积液、腹水」里的「腹水」保住否定）。现在极性提示词
  必须落在该提及**结束位置之前**才作用于它，两类写法同时正确。
* **不确定无条件压过否定**。「未见胸腔积液考虑胸膜粘连」丢掉了明确写出的「未见」。
  改为按提示词位置取舍；「不除外」仍按「不除外 优先于其中的 除外」处理。
* **尺寸取窗口里第一个数字**。「右肺上叶结节2.3cm、左肺下叶结节1.5cm」两个结节都报 2.3cm，
  改为取离该提及最近的数值。
* **数量词被屏蔽却抽不回来**。「一枚」「两枚」「成团」「簇状」在 `filler.count` 里却不在
  `attributes.count.cues` 里，于是报告明明写了数量，仍报「没写单发还是多发」；而且数量曾是
  整小句共用，「双肺多发结节、右肺上叶单发结节」会把后者错编成 Multiple Pulmonary Nodules
  ——**错的 MeSH 描述符**。现在两处词表同步，并按位置取最近的提示词。
* **组合不出概念时丢掉已绑定的部位**。「胸壁占位」里「胸壁」在整份输出中消失，
  `siteMentions=1` 而 `orphanSites=0`（自相矛盾），理由还写成「同一句内没有可供绑定的部位」。
  现在部位挂在未归一化项上，理由也如实写。
* 另有两处顺手修正：**「转移至肝」的部位优先级**提到同句兜底之前（旧顺序会绑到同句更远的
  「右肺」，再按规则给出 Lung Neoplasms —— 错的部位来源概念）；**未归一化理由里的
  `bowel wall thickening`** 只提到一种部位，改为涵盖胆囊 / 膀胱等全部别名，
  并去掉 reason 里手写的 MeSH 编号（随包数据不出现手写编号这条口径，reason 也该守）。
